# Methods {#sec:methods}

The pipeline is four stages — **discover → render → publish → research** — each a testable module in `src/fractiskills/`, driven by a `fractiskills` CLI. Network behavior is bounded by two reviewed files: the site spec `data/sources/ssvibelandia.yaml` (crawl limits, user agent, dynamic bindings) [@ssvibelandia] and the Skillarum crawl safety limits it feeds [@skillarum].

## Discovery

`discover.py` fetches and parses the declared sitemap (`{{SITEMAP_URL}}`, {{SITEMAP_URLS}} URLs) [@sitemaps], normalizing and validating every entry (absolute HTTP(S), same-origin against {{BASE_URL}}); failures are recorded, never guessed into existence. It then runs exactly **one bounded breadth-first crawl** through Skillarum's `WebsiteCrawler` [@skillarum], seeded with `/` plus every validated sitemap URL: `follow_links` enabled, prefix filtering, page/request caps, a minimum per-request delay per [@rfc9309], and streamed bounded reads. Redirect chains are captured as alias maps, so stub URLs resolve to the canonical page they forward to; for each sitemap URL not accepted as a page, one exact-page resolution fetch decides whether it forwards onto an accepted canonical (recorded as an alias) or is a distinct page. The union — sitemap ∪ crawl, deduplicated by canonical/final URL — is persisted as the page inventory (`output/data/inventory.json`) with `via_sitemap`/`via_crawl_only` provenance flags, BFS depth, outbound links, and aliases.

Sections are assigned mechanically: multi-segment paths take their area from the first path segment (`/journey/*` → `Journey`), `/interfaces/nesting/*` is promoted to `Nesting`, and single-segment deck-level pages join `Core`. This rule yields {{SECTION_COUNT}} sections over {{TOTAL_PAGES}} pages.

## Render

`profiles.py` compiles one Skillarum profile per section — {{SECTION_COUNT}} profiles — each with one exact-page target per discovered page, request budgets derived from the section's page count, and a minimum inter-request delay. `pipeline.py` runs each profile via `skillarum.pipeline.run_profile`, injecting the `AugmentedGenerator` described below. A hard target failure — a page vanishing between discovery and render — fails its section with a persisted `failure.json` manifest rather than a silent skip; partial renders are never presented as complete. The {{SECTION_COUNT}} profile runs cost {{REQUEST_COUNT}} network requests in total.

## Dynamic-document augmentation

`AugmentedGenerator` subclasses Skillarum's `DeterministicGenerator` [@skillarum], so every skill body keeps the deterministic section structure and passes Skillarum's portable-body validators. Bindings are declared in the site spec as `{id}`, `{last_segment}`, or `{path}` templates. For a matching page, the generator fetches the bound JSON endpoint — GET only, timeout-bounded, DNS-validated to the site's origin, same-origin enforced — extracts the document text from the payload HTML, and prepends a provenance header (endpoint, retrieval timestamp, HTTP status, content SHA-256, ETag) before replacing the shell text. Every attempt, successful or failed, is appended as a receipt to `output/data/augmentation_receipts.jsonl` and mirrored into the skill's manifest metadata. Of {{AUGMENT_ATTEMPTS}} attempts, {{AUGMENT_OK}} retrieved real documents ({{AUGMENT_CHARS}} characters) and {{AUGMENT_FAILED}} degraded honestly — static shell text published with an explicit warning, failure reason preserved in the receipt, so the rendered skill stays truthful about its thinness.

## Publish and research

`publish_skills` validates every rendered package with Skillarum's package validator, copies it into the tracked `skills/<Section>/<Skill>/` tree, reconciles stale packages away, and rebuilds the discovery index. The research stage (`analysis.py`, `figures.py`, `publication.py`) aggregates run manifests, augmentation receipts, and the published tree into one analysis record, renders the figures of §\ref{sec:visualizations}, and computes the manuscript token values. Token binding is loud: a token with no computed value fails the build rather than silently binding a placeholder into `output/manuscript/`. All {{SKILL_COUNT}} skills, figures, receipts, and the analysis CSV regenerate from a clean checkout with `uv run python -m fractiskills run --refresh --json` [@fractiskills].
